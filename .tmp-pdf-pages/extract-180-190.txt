2.5 Files Description 
Not everything the system stores is a database row. Binary content ΓÇö profile photographs, ticket 
attachments, maintenance evidence, guide images and firmware images ΓÇö is held in S3-compatible 
object storage (MinIO), and the database keeps only the metadata needed to find and authorise it. 
The bytes and the row describing them are therefore two separate things, which is what allows an 
attachment to be served directly to a browser without passing through a service.

07 Content type Derived from the file's own signature bytes rather than from the 
Content-Type the client declares, then stored with the object. A mis-declared 
header would otherwise make an image or document fail to open when 
served directly from the bucket. 
08 Access Reads are served either by a presigned URL with a bounded lifetime or 
through the service, which checks the caller against the file's purpose before 
streaming it. Every upload and download is written to file_audit_logs with 
the actor and the outcome.

3. Detailed Design 
Each subsection below covers one feature: the class diagrams of the participants in its main flows, 
followed by a specification of every class in them. The pipeline is the same throughout ΓÇö a controller 
forwards a command to the mediator, a validation behaviour runs before the handler, the handler 
works through repository interfaces, and the unit of work commits the state change together with 
the outbox rows it produced. 
3.1 Account Registration and Activation 
Owning service: AuthService 
Registration creates an inactive account and defers activation to an emailed one-time code. The 
password is hashed with BCrypt inside the handler and the plaintext never leaves the request scope. 
188 
 
The verification email is not sent inline: the handler writes the integration event to the outbox in the 
same transaction as the account row, so an account is never created without its email being queued 
and never has an email queued without being created.
